## 简化方式

按接触作用重新建模，不再保留每个小凸台和原分块边界。当前包含8个基础几何（4圆柱、4盒体）和57个mesh形状：

| 部位 | 数量 | 表示方式 |
| --- | --- | --- |
| 机身 | 1 | 原凸包；单外接盒体会填占前后腿空间，因此未采用 |
| 髋部 | 4 | 每髋1个原凸包 |
| 大腿 | 44 | FL/RL各10个，FR/RR各12个；电机、两侧板、圆柱外壳、过渡盒体及少量通道/挡壁凸块 |
| 小腿 | 12 | 每腿3个原分段凸块，保留固定碰撞载体 |
| 足端 | 4 | 原独立足端及STL碰撞，尺寸、位置和最低点不变 |

大腿几何的含义：

- `thigh_housing`：XZ平面半径40 mm、沿Y方向长25 mm的圆柱，中心Y为左右镜像的±51.2 mm。近似上部外壳，忽略内部小腔体，不把整个活动槽填成实心。
- `thigh_transition`：厚3 mm、沿Y方向25 mm的斜向盒体，近似上部到长槽的过渡壁。
- `thigh_channel_back/front/tip`：保留原主壁及末端凸网格，只改语义名称。局部 `Z=-130 mm` 代表截面的主槽净宽仍为31 mm，不沿用旧77形状版约23.22 mm的错误填充。
- `thigh_fold_guard_*`：原折膝接触面的凸网格；左侧1块、右侧3块，源于左右原CAD分块不同，不为数量相等而填平边界。
- `thigh_lower_rim`：下部外缘的单个低面数凸包。长槽内小凸台不再独立描述，原始显示不变。

这是接触代理近似，不是原169形状的逐点等价替换。上部装配腔体、局部凸起和过渡轮廓有变化；主槽净宽不变不代表所有空腔与表面距离均不变。保留中空大腿的关键运动通道，不用整根实心胶囊或6 mm填充预算。

## 机械与导入契约

- 总质量仍为 `12.04293025733458 kg`；各link的质量、质心、惯量及关节坐标/轴向不变，不能按碰撞体体积重算惯量。
- 12个理想关节执行器限矩 `±23.7 N m`。小腿机械范围 `[-2.7227, -0.8378] rad`，不以收紧到 `-2.4 rad` 代替接触。
- 默认角按FL/FR/RL/RR排列，每腿 `[0, -0.75, -1.5] rad`。XML的body姿态与joint.ref成对补偿，默认加载、home、YAML一致。
- 四个 `*_calf_collision_link` 与小腿刚性连接，不新增DOF；载体和原小腿各占原质量/惯量的一半，质心相同，复合动力学不变。
- 足端只承载足端接触。训练非足端接触选择包含 `calf`，从而包含固定载体，不能把小腿接触归到足端。
- 训练使用 `collapse_fixed_joints=False`、`self_collisions=-1` 及原20对命名排除。新增 `replace_cylinder_with_capsule=False`，禁止自动把圆柱扩成胶囊，使训练和MuJoCo端面一致；Go2不变。
- MuJoCo保留 `filterparent=disable` 与原掩码，不关闭大腿/小腿、不同腿之间的自碰撞。通用位1、机身2、FL/FR/RL/RR髋4/8/16/32、对应大腿电机64/128/256/512；双方都拒绝对方才排除接触。

训练与部署的URDF、引用网格、JSON须一致。`PrimuusEnv / PrimuusCfg / PrimuusCfgPPO` 直接继承通用base，不导入Go2；XML只由部署维护。

## 参数与检查

PD暂用 `20 / 0.5`，动作缩放0.25。物理步长0.25 ms，PD每步更新，策略每80步更新（50 Hz）。MuJoCo接触响应0.5 ms、每几何margin 1 mm；Primuus训练contact_offset 1 mm、rest_offset 0.5 mm、位置/速度迭代8/2。本次不改这些参数、奖励或观测。相同电机不代表不同结构的控制效果相同。

地面摩擦 `0.8 0.005 0.0001` 是当前仿真假设，不是实物辨识值。虚拟IMU位于base原点，不代表实物安装位置。

本地MuJoCo 3.8.1检查，仅模型，不运行策略或训练：

- 默认姿态无自碰撞穿入。1000组强制姿态包含200组站姿附近采样、800组全限位随机角；原模型无穿入的785组在新模型均未新增穿入。限位内任意组合不一定可达。
- 四腿各401个小腿角度扫描未新增提前穿入，新旧首次负距离采样角均约 `-2.633167 rad`。最小距离不逐值相等，非接触区最大差异约2.5 mm。
- 默认角PD保持4 s、倒地2 s、侧倒2 s、关节摆动4 s均无数值警告，采样没有负自碰撞距离；新轨迹放回旧169形状包络复查也未记录到穿入。
- 固定机身、髋和大腿，四小腿施加 `-23.7 N m` 折膝3 s，新旧停止角逐项相同，约 `-2.617338 rad`，不是机械限位截断。
- 当前PD站立4 s末态机身Z仍约0.234 m，与旧模型相同，低于高度奖励0.25 m的容差下限，仍需后续调参。

有限检查不证明CAD同姿态运动学已全部核对，也不保证任意冲击下数学意义的零穿入。直接改qpos或拖滑块会绕过物理过程，可强行放入相交姿态。

### 服务器10轮检查

2026-10-16，以训练提交 `b51c6c9` 的65形状资产和Primuus配置，在RTX 3090 Ti、Python 3.8、PyTorch 2.4.1+cu121的现有环境执行：

```bash
python quadruped_rl/scripts/train_primuus.py --headless --num_envs 4096 --max_iterations 10
```

- 使用GPU PhysX与GPU pipeline，完成10次采样/优化迭代，共983040个环境步；进程退出码0，包含初始化的总耗时约238 s，每轮约22 s，约4300-4400 steps/s。
- 成功保存 `model_10.pt`，checkpoint迭代数10；30个模型状态tensor和800个TensorBoard标量样本均无NaN/Inf。退出后显存恢复到启动前水平。
- 未复现旧初始化崩溃，也未发现CUDA/PhysX错误或显存不足；仅有 `torch.meshgrid` 未来需要显式indexing的兼容性警告。首次非交互SSH启动缺少Conda bin路径、找不到已安装的Ninja，为本次进程补齐PATH后重跑通过，未安装软件或改系统配置。
- 日志、状态、校验结果和checkpoint归档到服务器 `/tmp/primuus-smoke10-65shape-20261016_163317/`；本次测试run已从正式 `logs/primuus/` 移出，避免被默认最新run选择。测试策略不作为可用运动策略。

**这只确认65形状模型的短程GPU训练链路可运行，不代表收敛、步态、长期稳定性或sim2sim已经验收，也没有修复底层SDK对旧169形状模型的内存越界。** 没有修改驱动、CUDA、PhysX库、聚合容量或自碰撞开关，没有做CPU PhysX单独验收，也不宣称相对旧模型的加速倍数。一次性检查脚本、截图和测试产物不加入正式链路。

## 查看与部署

部署工程根目录：

```bash
python3 -m mujoco.viewer --mjcf=src/controller/rl/resources/robots/primuus/scene_flat.xml
```

默认足端距地约2 mm。仅看静态姿态时空格暂停；裸查看器不读YAML、不运行PD，直接播放倒地不能判断站立控制效果。查看碰撞时关闭Geom group 2、开启3，并开启 **Convex Hull**，否则STL可能仍按显示网格渲染。外观统一浅银灰。

当前没有经过运动效果验收的Primuus策略，10轮测试checkpoint不作为部署策略，YAML仍预留 `models/primuus/policy.pt`。正式策略到位并核对观测、PD与动作契约后：

```bash
python3 src/controller/rl/rl_controller/deploy_mujoco_rl.py \
  --config src/controller/rl/config/primuus.yaml
```

缺少策略时正式入口会拒绝启动，不得用Go2策略代替。本次不改Go2模型、训练任务或默认部署入口。
