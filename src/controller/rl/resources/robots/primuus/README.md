# Primuus 仿真资源

[RL子工程说明](../../../README.md) | [运行配置](../../../config/primuus.yaml)

模型状态核对日期：2026-10-16。已撤销侵占长槽净空的77形状版本，恢复原169形状模型的通道边界；只对机身和四个髋部预生成等价凸包。训练侧已独立注册 `primuus`，但尚未完成训练或提供匹配策略。模型检查不等于CAD同姿态核对或GPU训练验收完成。

本目录仅描述当前 Primuus 的简化关节力矩模型，用于 sim2sim 准备，不模拟齿轮和连杆传动。

## 文件职责

| 文件 / 目录 | 作用 |
| --- | --- |
| `urdf/primuus.urdf` | 17 个原始物理部件及 4 个固定碰撞载体：12 个转动关节、8 个固定关节及质量惯量 |
| `stl/` | 17个原始显示网格，保持CAD几何不变；足端碰撞仍引用原始STL |
| `collision/*_thigh_motor.STL` | 从原始大腿中分离的电机碰撞网格 |
| `collision/*_thigh_plate.STL` | 离线拆分板件的来源，不再直接作为运行时的单个凸包 |
| `collision/convex/` | 原156个凸分块原样保留，另加机身与四个髋部的5个等价凸包，共161个OBJ；URDF/XML共用相同网格 |
| `collision/self_collision_exclusions.json` | 正常装配接触的 20 对命名几何；供训练侧通用过滤接口使用 |
| `primuus.xml` | MuJoCo 本体：保留 URDF 的关节坐标和完整惯量，增加浮动机身、执行器、虚拟 IMU 和传感器 |
| `scene_flat.xml` | 引用本体并加入地面、灯光和相机；不复制机器人结构 |
| `../../../config/primuus.yaml` | 机器人运行配置：模型和策略路径、关节顺序、PD、默认姿态及观测契约 |

XML 使用相对于本目录的网格路径，不依赖最初的 CAD 导出目录。修改 URDF 的结构、惯量、坐标或碰撞后，必须同步 XML 并复核；两者不会自动同步。

URDF 与 XML 的机身及四条腿统一使用浅银灰色 `RGBA=(0.898039, 0.917647, 0.929412, 1)`，XML 碰撞几何的显示颜色也保持一致。颜色仅影响渲染，不改变碰撞或动力学；原始 STL 不修改，光照与阴影仍会产生明暗差异。

XML 的大腿、小腿 `body.quat` 和 `joint.ref` 成对补偿，使默认加载姿态与 `home` / YAML 的默认角一致，避免全零小腿角超出限位、初始足端穿入地面。外部关节角的含义仍与 URDF 一致，不能只改 `ref` 而不更新对应的 body 姿态。

## 碰撞约定

- 和 Go2 一样分离显示与碰撞几何，但不复制 Go2 的尺寸。大腿的两侧板、通道壁和局部凸台分别建模，避免一个凸包把小腿活动通道填满。孔洞和边缘采用保守近似，不表示逐三角面精确碰撞。
- 每腿保留原32个 `*_thigh_wall_00..31.obj` 通道壁，以及原内外侧板、隔柱、局部凸台和电机碰撞网格；它们与原始169形状版本 `d8806b4` 的文件字节一致。不合并凹口、不侵占槽内空间、不扩大接触裕量来代替几何修复。
- 机身和四个髋部各使用一个独立的 `*_collision_hull.obj`。它们只从原STL中提取凸包顶点、剔除内部面与冗余顶点，不缩放、不移动、不做顶点近似；原有普通mesh碰撞本就使用该凸包，因此不改变原碰撞外包络。原STL继续用于显示。电机、小腿和足端维持原输入网格，避免重排关键网格带来额外的距离查询差异。
- 小腿原来的整块凸包会填平弯折轮廓，造成约 `-2.45 rad` 的过早接触。现在从主杆网格沿局部 Z 轴 `-0.145 m`、`-0.01 m` 截分为三个凸包，不再用一个凸包覆盖整个小腿。轴心的小螺帽只保留显示。
- 每条小腿的碰撞几何位于同坐标的固定子 link `*_calf_collision_link`，避开 PhysX 对直接父子 articulation link 的强制过滤，使大腿与小腿碰撞真正参与求解。载体不是新机械零件，不增加自由度。原小腿质量和惯量在原 link、载体中各占一半，质心坐标相同，总质量、复合惯量和运动学不变；不能给载体省略惯量，否则导入器可能按碰撞体体积生成额外质量。
- 足端仍是独立的 `*_foot_link`，其碰撞几何不承载小腿，避免把小腿接触误记为足端支撑。训练侧的非足端接触选择须包含 `calf`，不能仅按原 `*_calf_link` 精确名称采集力，因为接触发生在固定载体上。
- MuJoCo 在本模型内关闭父子过滤，并用 `contype/conaffinity` 仅排除机身与髋安装处、髋与本腿大腿电机安装处。固定足端、碰撞载体和本腿小腿属于同一焊接组，不产生内部碰撞。大腿板件与髋、小腿与大腿、足端与大腿及不同腿之间均可产生接触。
- 碰撞位为：通用几何 `1`，机身 `2`，FL/FR/RL/RR 髋 `4/8/16/32`，对应大腿电机 `64/128/256/512`。双方的兼容掩码均拒绝对方才排除，其他组合保持启用。不要把 `filterparent` 改回默认值来消除接触。
- 四条腿小腿范围恢复为机械交付值 `[-2.7227, -0.8378] rad`。撤销没有机械依据的 `-2.4 rad` 下限；由接触阻止几何继续互穿，不再以缩小活动范围替代自碰撞修复。
- MuJoCo 的物理步长为 `0.25 ms`、接触响应时间为 `0.5 ms`，接触裕量为每个几何 `1 mm`。原 `1 ms` 步长与较软接触在最大力矩快速折膝下可能瞬时穿入薄壁；缩小步长并提高接触阻抗用于处理这种离散碰撞，而不是改变关节轴向或零位。小腿限位响应仍为 `2 ms`。
- 关节范围不是任意姿态都无碰撞的保证。手工赋值 `qpos` 或拖动滑块可直接把模型放入几何相交姿态，绕过正常运动过程；接触约束需要随物理步求解。有限步长和软接触也不能保证任意冲击下数学意义的绝对零穿入。

原始 STL、总质量和复合惯量、驱动关节坐标及默认姿态不变。模型更新时必须同步凸分块引用、固定载体惯量和过滤规则，不能只替换显示文件。当前已确认的是碰撞过滤和凸包表示问题，没有证据证明 CAD 中的轴向、零位或运动关系错误；仍未完成与 SolidWorks 同一姿态的运动一致性核对。

### 训练侧接入边界

训练工程已经注册独立的 `PrimuusEnv / PrimuusCfg / PrimuusCfgPPO`，均直接继承通用 base，不导入 Go2。训练侧 `resources/robots/primuus/` 包含与本目录一致的 `urdf/`、`stl/`、`collision/`；XML 场景只由部署侧使用。模型更新时必须同步完整 URDF 引用资产，不能只拷贝 `stl/`。本次接入不代表已有策略或已完成训练验证。

训练侧 `PrimuusCfg.asset` 读取自身目录中的 JSON 列表，设置 `self_collisions=-1` 保留配置后的过滤位，并保持 `collapse_fixed_joints=False`、一份预分解凸网格对应一个 collision。导入形状数量或名称不一致时会报错，不会静默关闭碰撞。足端和碰撞载体的八个固定关节均标记为 `dont_collapse`，必须保留载体，否则会重新触发直接父子过滤。

当前共21个link、12个驱动关节、169个碰撞形状；4个载体和原小腿刚性连接，不改变12维动作或 `45 * 6` 观测。形状组成是机身1个，每腿髋1个、大腿37个、小腿3个、足端1个。本次优先保留全部原活动空间，数量不再以77为目标。没有改变质量惯量、原始显示STL、关节坐标/限位、20对命名排除、PD或接触求解参数。

Isaac Gym 的 `self_collisions` 是数值过滤参数：`0` 开启可用自碰撞（仍过滤相邻 link），正数关闭全部自碰撞，`-1` 使用资产过滤位；不是 `False/True` 意义的启用开关。不要沿用 Go2 当前的 `1` 来接入 Primuus。

### 接触求解设置

原169形状模型的服务器CPU PhysX验证采用以下设置；当前机身/髋部已改用等价预生成凸包，仍需独立做PhysX导入验收，不能仅引用旧结果，也不能直接覆盖Go2配置：

| 参数 | 数值及含义 |
| --- | --- |
| `sim.dt` / `sim.substeps` | `0.001 s` / `4`，物理子步为 `0.25 ms` |
| `sim.physx.contact_offset` | `0.001 m`，每个形状的接触检测距离 |
| `sim.physx.rest_offset` | `0.0005 m`，每个形状的静止接触偏移，给数值求解保留余量 |
| `asset.thickness` | `0.001 m`，导入碰撞厚度 |
| PhysX 求解迭代 | 位置 `8`、速度 `2` |

正式Primuus训练配置使用 `sim.dt=0.00025 s / substeps=1 / decimation=80`，与MuJoCo XML/YAML一致，策略50 Hz，PD每个物理步更新。单形状的接触和静止偏移也由资产配置显式应用。它与上表CPU检查的主步长和PD频率不同，不能将旧结果当作当前PhysX训练配置通过；不要直接改回Go2的 `5 ms / 1`。

### 旧版接触检查（169形状）

- 150 组随机位姿的原有部件位置、旋转不变，质量矩阵与重力/科氏项最大差异约 `1.5e-14`；总质量仍为 `12.04293 kg`。此项对比不等于已经验证 CAD 运动一致性。
- MuJoCo 检查各 8 秒的无控制倒地、PD 站立、持续 `23.7 N m` 折膝、关节摆动与侧倒，无数值警告，测试中未记录到自碰撞几何的负接触距离。复查末态及最深折膝附近共 60 条腿姿态的原始显示三角面，未发现膝轴正常装配区域 25 mm 以外的大腿/小腿相交。
- MuJoCo 的最大力矩折膝由真实接触停止在约 `-2.617 rad`，不是通过 `-2.4 rad` 限位截断。PD 站立机身高度约 `0.294 m`，仅足端接触地面。
- 服务器 CPU PhysX 导入 21 个 body、12 个关节和 169 个碰撞体；原始小腿下限保留 `-2.7227 rad`，倒地和固定机身最大力矩折膝均检测到大腿与小腿载体接触。命名过滤接口无需修改，足端仍保持独立。
- PhysX 的 `rest_offset=0` 基线在极值采样中仍有约 `0.323 mm` 的原始网格穿入。采用上表的 `0.5 mm` 单形状静止接触偏移后，最大力矩折膝采样未发现相交，但倒地极值采样仍约 `0.104 mm`；这是尚存的数值接触误差，不能描述为所有引擎、所有工况绝对零穿入。
- 当时没有运行GPU PhysX或GPU训练验证，因为服务器已有训练占用GPU；没有中断或修改该训练。Go2原有MuJoCo正式入口的两秒回归通过。

以上仅保留为旧模型检查背景，不是策略行走验收、4096环境训练或当前版本性能基准。

## 当前参数

- 12 个执行器均按关节端力矩解释，控制输入和执行器力矩限制均为 `[-23.7, 23.7] N m`；URDF 的 effort 同步为 23.7。
- 默认姿态按 `FL / FR / RL / RR` 排列，每腿为 `hip=0、thigh=-0.75、calf=-1.5 rad`。
- YAML 与独立训练任务均使用 `kp=20、kd=0.5`，先沿用 Go2 的训练基线；此前模型接触检查使用 `60 / 1.5`，不能把该站立结果当作当前增益已经验收。相同电机并不保证不同机械结构具有相同控制效果，后续仍需分别调参。
- 物理步长为 `0.00025 s`，策略每 80 步更新一次，即 50 Hz；PD 由现有运行器逐物理步更新。
- 地面和碰撞网格摩擦采用当前测试假设 `0.8 0.005 0.0001`。不模拟电机热限制、转速-力矩曲线或额外传动。
- XML 的 `imu` 是放在 `base_link` 原点的虚拟传感器，不代表实机安装位置。

## 查看模型

在工程根目录执行：

```bash
python3 -m mujoco.viewer --mjcf=src/controller/rl/resources/robots/primuus/scene_flat.xml
```

默认加载和 `home` 关键帧均为与 YAML 一致的参考位姿，足端初始距地约 2 mm。查看器不会读取 YAML 或自动运行 PD；直接播放没有控制器的模型仍会倒地，不能用它判断站立控制效果。仅检查静态姿态时按空格暂停，再调整 Joint 面板。

查看实际碰撞包络时，在Geom groups中关闭2（原始显示网格）、开启3（碰撞），并在可视化选项中开启 **Convex Hull**。仅关闭显示组并不保证网格按实际凸包渲染；原输入STL的螺孔、端盖细节可能仍可见，但不表示物理碰撞会保留这些孔洞。机身和髋部的碰撞源现在已经是独立凸包，原始CAD显示网格没有修改。

## 策略配置

当前没有 Primuus 专用策略。`config/primuus.yaml` 的 `policy_path` 预留为 `models/primuus/policy.pt`，可以改为真实 Primuus TorchScript / ONNX 文件的路径。不得用 Go2 策略代替。

实际策略到位，并确认默认姿态、PD、动作顺序、45 * 6 观测和缩放参数与训练侧一致后，使用现有入口：

```bash
python3 src/controller/rl/rl_controller/deploy_mujoco_rl.py \
  --config src/controller/rl/config/primuus.yaml
```

策略缺失时配置检查会拒绝启动，这是当前预期行为。本次没有添加无策略 PD 模式，也没有修改 Go2 的默认入口或配置。
