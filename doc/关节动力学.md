# Primuus 关节损耗

Primuus 的训练与 MuJoCo 部署使用相同的 Jenkins 弹簧—滑块模型，加上粘性阻尼。Go2 保留自己的原生关节动力学，不引用 Primuus 的定义。

## 参数与单位

参数位于两侧机器人资源目录的 `joint_dynamics.json`，代码位于训练 `quadruped_rl/utils/joint_dynamics.py` 与部署 `rl_controller/core/joint_dynamics.py`。这两份参数和算法应逐字节同步；训练工程不依赖本地部署目录。

| 字段 | 定义 | 数值 |
| --- | --- | --- |
| `coulomb_torque` | 干摩擦屈服力矩，N m | 0.05 |
| `viscous_damping` | 物理粘性阻尼，N m s/rad | 0.02 |
| `presliding_stiffness` | 预滑移扭转刚度，N m/rad | 5.0 |
| `joint_names` | 12 个关节的显式顺序 | FL/FR/RL/RR，每腿 hip/thigh/calf |

这些是仿真假设，不是电机实测辨识值。前两项取 MuJoCo 原有数值作为非零基线，不代表 PhysX 原生摩擦系数的等效换算；刚度决定微位移尺度，需要用实物的低速、起动和反向数据进一步标定。没有依据时不额外引入载荷相关、温度或 Stribeck 参数。

## 力矩计算

每个物理步，从实际关节位置增量更新内部预滑移状态：

```text
z = clip(z + (q - q_previous), -Fc / k, Fc / k)
tau_passive = -k * z - b * dq
```

`z` 是微观弹性变形的等效角度，不是关节目标位置。未到屈服力矩时保留弹性保持作用；达到屈服后，干摩擦分量饱和为 `+/-Fc`，不限制粘性分量。反向时按实际位移卸载，再建立反向摩擦。

例如从未预载的静止状态施加恒定 `0.025 N m`，预滑移平衡偏移为 `0.025 / 5 = 0.005 rad`。这是有限微位移，不应表现为持续匀速蠕动。模型不通过修改 `qvel`、位置钳制或速度死区制造静止。

内部弹性能为 `k*z*z/2`。反向时可释放已储存能量，所以不能单用瞬时 `tau_passive*dq <= 0` 判断耗散性；应同时核对摩擦做功、弹性能和离散积分误差。该显式耦合不承诺任意步长下严格被动或稳定，变更步长、惯量或刚度需要重新检查响应。

模型依据为经典 Jenkins 元件的弹簧串联库仑滑块思想，见 [pyHarm 元件说明](https://pyharm-saf.readthedocs.io/en/1.1.3/NodeToNodeElements.html#jenkins)。预滑移与持续漂移的区别可参考 [Dupont 等的弹塑性摩擦论文](https://cim.mcgill.ca/~haptic/pub/PD-VH-BA-FA-TAC-02.pdf)。这里只采用简单 Jenkins 模型，不宣称完整实现论文中的所有摩擦效应。

## 引擎接入

```text
策略目标 -> PD -> 电机限矩 -> tau_motor
关节位置/速度 -> 被动损耗 -> tau_passive
物理引擎接收 tau_motor + tau_passive
```

- 训练：`PrimuusEnv` 在运行时将 PhysX 原生 DOF friction/damping 置零，并加入上面的非零模型，避免重复损耗；`torques` 和力矩奖励仍只表示限幅后的电机力矩，另存 `passive_joint_torques`、`net_joint_torques`。
- MuJoCo：YAML 的 `simulation_joint_dynamics_path` 显式选择模型。电机力矩进入 `ctrl`，被动损耗进入受控关节的 `qfrc_applied`；不覆盖机身外力通道，也不扩大执行器限矩。
- 实机：不施加这项虚拟损耗。真实关节已有摩擦，不能在真实电机输出上再次叠加仿真摩擦。

机器人质量、质心、惯量、armature、地面摩擦、碰撞过滤和关节限位不随此模型改变。PD 的 `kd` 是控制反馈增益，不是物理阻尼 `b`。

URDF/XML 保留原始动力学数值，Python 适配器仅在启用替代模型时覆盖关节损耗。因此裸 `mujoco.viewer` 仍使用 XML 原生损耗；策略部署应使用 `deploy_mujoco_rl.py --config .../primuus.yaml`。这两种打开方式不是同一套控制/损耗运行路径。

## 一致性的含义

两端共用的是关节损耗的物理定义，而不是原生摩擦参数的常数换算。在相同关节位移历史、速度和初始预滑移状态下，NumPy与Torch实现按同一公式计算力矩；只有位置与速度相同、历史状态不同，保持力矩仍可能不同。

此定义不替换足地接触摩擦。接触求解、物理步长和状态估计的域差异仍会影响整机运动；同一关节公式不能保证两端轨迹逐帧相同。修改 `domain_rand.friction_range`改变的是形状接触摩擦，不会自动随机化关节参数。

## 状态与策略契约

每步只更新一次摩擦状态；策略更新频率不决定摩擦更新频率。环境复位和 MuJoCo 重置都清除预滑移历史，并以新位置作为增量基准，避免瞬移被误判为高速滑动。跌倒后关闭电机输出，但被动摩擦仍存在。

定义文件缺失、格式不支持、参数非正或关节顺序不符时直接报错，不静默退回 Go2 或原生损耗。

改变损耗模型会改变策略所见动力学。旧模型训练的策略不能视为与新模型兼容；统一损耗的目的不是调参迁就旧策略，而是让之后的训练和部署使用明确一致的物理假设。它也不消除两引擎的接触求解差异或速度估计器的域偏差。
