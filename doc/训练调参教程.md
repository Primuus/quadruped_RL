# quadruped_train 训练调参教程

这份文档用于记录当前 `quadruped_train` 的调参方法。重点说明正式参数如何生效、哪些数值会明显影响训练、哪些改动可以续训、哪些改动需要从头训练，以及哪些训练侧改动需要同步到本地部署侧 `quadruped`。

当前训练代码位置：

```bash
cd ~/quadruped_train
```

当前主要配置文件：

```text
quadruped_rl/envs/base/legged_robot_config.py   # 四足机器人通用默认配置
quadruped_rl/envs/go2/go2_config.py             # Go2 当前实例配置
quadruped_rl/envs/base/domain_rand.py           # 域随机化和外推逻辑
quadruped_rl/envs/base/rewards.py               # reward 状态依赖声明
quadruped_rl/envs/base/legged_robot.py          # reward 函数、观测、环境主逻辑
```

## 参数如何生效

当前框架已经去掉阶段验证时期的 `safety gate`。每项功能只保留一个正式配置来源：

| 功能 | 唯一生效参数 |
| --- | --- |
| reward | `rewards.scales.<name>`，非零启用，零关闭 |
| 观测噪声 | `noise.add_noise` |
| 摩擦随机化 | `domain_rand.randomize_friction` |
| 质量随机化 | `domain_rand.randomize_base_mass` |
| 随机外推 | `domain_rand.push_robots` |
| 速度命令课程 | `commands.curriculum` |
| 地形课程 | `terrain.curriculum` |
| 高度采样 | `terrain.measure_heights` |

45×6 历史观测、`HIMActorCritic`、`HIMPPO` 和 `HIMOnPolicyRunner` 是当前框架结构，不再通过额外布尔量启用。`foot_clearance` 权重非零时，环境会自动获取并刷新它需要的 rigid-body state。

## 新增 reward 或域随机化

这一节说明的不是“把已有参数从 `0.0` 改成非零”，而是给框架增加一个以前不存在的 reward 或随机化项时，代码应该放在哪里、哪些地方必须同步修改。

先区分两类需求：

```text
已有 reward / 随机化项，只是启用或调权重：通常只改 Go2 配置。
以前不存在的新项：需要配置 + 实现；实现放在通用层或机器人适配层，并显式声明额外状态依赖。
```

训练侧的分层约定如下。以后新增其他四足机器人时，通用逻辑保持在 `base`，机器人差异放在对应机器人目录，避免把 Go2 专有逻辑写进框架核心。

| 位置 | 负责内容 | 新增时是否通常需要改 |
| --- | --- | --- |
| `quadruped_rl/envs/base/legged_robot_config.py` | 所有四足机器人的默认配置、默认关闭的开关和注释 | 是，新增通用配置字段时 |
| `quadruped_rl/envs/go2/go2_config.py` | Go2 的实际权重、范围和开关 | 是，给 Go2 启用或覆盖参数时 |
| `quadruped_rl/envs/base/legged_robot.py` | reward 计算、状态 buffer、reset 和物理步主流程 | 新 reward 或动态随机化时 |
| `quadruped_rl/envs/go2/go2_env.py` | Go2 任务适配器，可覆盖 Go2 专有行为 | 仅公式或行为确实只适用于 Go2 时 |
| `quadruped_rl/envs/base/rewards.py` | reward 所需额外状态的集中声明 | 新 reward 依赖额外状态 tensor 时 |
| `quadruped_rl/envs/base/domain_rand.py` | 资产属性随机化和 push | 新增域随机化实现时 |
| `quadruped/src/controller/rl/...` | 本地 MuJoCo 推理 | 仅 reward/随机化通常不用改 |

### 先确认是不是已有项

先在训练仓库查找同名函数和配置：

```bash
cd ~/quadruped_train
rg -n "base_height|foot_clearance" quadruped_rl/envs
```

例如当前已有 `_reward_base_height()`。若只是让它参与训练，不要再写函数，只需要在 Go2 配置里把权重从 `-0.0` 改为非零：

```python
# quadruped_rl/envs/go2/go2_config.py
class rewards(LeggedRobotCfg.rewards):
    class scales(LeggedRobotCfg.rewards.scales):
        base_height = -0.5  # 高度误差是代价，因此使用负权重
```

这种改动不改变 actor、critic、观测或动作维度。可以用 checkpoint 续训，但因为优化目标变了，短期曲线下降是正常现象。

### 新增一个 reward 的完整步骤

以下以假设的 `foot_slip` 为例。它惩罚“足端接触地面时仍有较大水平速度”，适合作为步态稳定后的可选约束。示例只说明接入方式，具体公式和初始权重必须根据训练现象决定。

#### 1. 先定义名称和数值方向

名称必须在配置和函数名中完全一致：

```text
配置 key:       foot_slip
环境函数:       _reward_foot_slip(self)
TensorBoard:    Episode/rew_foot_slip
```

当前框架会自动寻找每一个非零 scale 对应的 `_reward_<名称>` 函数；不需要手动把它注册到 `compute_reward()`。

权重的正负由函数返回值的含义决定：

```text
函数返回“越大越好”的量，例如成功率、速度跟踪得分：正权重。
函数返回误差、能耗、碰撞次数等“越小越好”的代价：负权重。
```

`foot_slip` 返回的是速度平方代价，所以应从负权重开始。不要为了使用正权重而在函数里额外取负；统一由 scale 表达奖励或惩罚，调参更容易比较。

#### 2. 在配置中声明，但默认关闭

如果该 reward 对所有四足机器人都有相同语义，先在 `quadruped_rl/envs/base/legged_robot_config.py` 的 `rewards.scales` 中加入字段，并写中文注释：

```python
class scales:
    # ...已有项...
    foot_slip = -0.0  # 足端接触时的水平滑动惩罚，默认关闭
```

默认使用 `-0.0`，原因是 `_prepare_reward_function()` 会移除 scale 为零的项。这样所有尚未验证的机器人默认不会因为缺少实现或数据依赖而启用该项。

若公式只对 Go2 成立，例如依赖 Go2 特有的 body 名称、关节结构或机构参数，则可以只在 `go2_config.py` 的 `rewards.scales` 中声明，并保持其他机器人配置没有该字段。不要把这种特例放进通用默认配置。

#### 3. 在具体机器人配置中给出初始权重

在 `quadruped_rl/envs/go2/go2_config.py` 中覆盖，而不是直接修改 Go2 以外机器人也会继承的默认值：

```python
class rewards(LeggedRobotCfg.rewards):
    class scales(LeggedRobotCfg.rewards.scales):
        foot_slip = -0.02  # 起始值；先用小权重验证，不要一次压制步态探索
```

新 reward 的首轮权重应明显小于速度跟踪主项。先让 TensorBoard 显示它的量级，再决定是否增强；不要只凭不同 reward 的原始数字直接比较，因为每项单位和公式不同，且框架会把非零 scale 乘以控制周期 `dt`。

#### 4. 在正确的环境层实现向量化函数

对所有四足都成立的公式，放在 `quadruped_rl/envs/base/legged_robot.py` 的 reward 区域。只适用于 Go2 的公式，则放进 `quadruped_rl/envs/go2/go2_env.py`，由 `Go2Env` 覆盖或新增同名方法。`Go2Env` 继承 `LeggedRobot`，所以自动发现机制会查找到两种位置的函数。

无论放在哪里，函数都必须返回形状为 `(num_envs,)`、位于 `self.device` 上的 tensor；不要为 4096 个环境写 Python 循环。下面以通用层的实现为例：

```python
def _reward_foot_slip(self):
    # 接触足端的水平速度平方和；返回值越大表示滑动越明显。
    foot_contact = self.contact_forces[:, self.feet_indices, 2] > 1.0
    foot_speed_sq = torch.sum(torch.square(self.feet_vel[:, :, :2]), dim=-1)
    return torch.sum(foot_contact * foot_speed_sq, dim=1)
```

当前 reward 执行链路是：

```text
Go2 rewards.scales.foot_slip 非零
        -> LeggedRobot._prepare_reward_function() 自动找到 _reward_foot_slip
        -> 每个控制步由 compute_reward() 调用并累计到 episode_sums
        -> 回合结束时自动写入 Episode/rew_foot_slip
```

因此，除 `termination` 这个特殊项外，不需要改 `compute_reward()`、`episode_sums` 或 TensorBoard logger。

#### 5. 处理额外状态依赖

`foot_slip` 用到 `self.feet_vel`，它来自 Isaac Gym 的 rigid-body state。此类 reward 需要在集中依赖集合中声明：

```python
# quadruped_rl/envs/base/rewards.py
QUADRUPED_RIGID_BODY_STATE_REWARDS = frozenset({
    "foot_clearance",
    "foot_slip",
})
```

环境会检查这些 reward 的权重：只要其中任意一项非零，就自动获取并刷新 rigid-body state。权重全部为零时不会承担这部分状态刷新开销。

若新 reward 只使用已有的 `dof_pos`、`dof_vel`、`actions`、`base_ang_vel`、`projected_gravity` 或 `contact_forces`，不需要修改 `base/rewards.py`。reward 本身的非零 scale 就是启用开关，不再增加第二套布尔 gate。

如果某项计算成本很高，仍然应使用 `rewards.scales.<name> = 0.0` 关闭；`_prepare_reward_function()` 会直接移除对应函数，不会在每个控制步调用它。

#### 6. 新 reward 的最小验证流程

```bash
cd ~/quadruped_train
python quadruped_rl/scripts/train_go2.py --headless --max_iterations 5
```

先确认没有以下问题，再做长训：

- 启动阶段出现 `AttributeError: _reward_xxx`：scale 名称与函数名不一致，或漏写函数。
- reward shape 报错：函数没有对足端、关节等维度做 `sum(..., dim=1)`，返回了 `(num_envs, num_feet)` 等二维结果。
- CUDA 相关报错：检查 tensor 是否在 `self.device`、是否混用了 CPU tensor，以及是否存在 Python 标量/布尔判断作用于 GPU tensor。
- TensorBoard 没有 `Episode/rew_xxx`：检查 scale 是否非零，并等待至少一个 episode 结束。
- 总 reward 上升但机器人变差：单独查看新项、速度跟踪、episode length 和 play 画面，不能只看 `Train/mean_reward`。

### 新增一个域随机化的完整步骤

域随机化不会新增 actor 输入。它做的是让相同的观测和命令对应不同但合理的物理条件，策略因此学习鲁棒行为。普通 reward 与域随机化都不需要同步到 MuJoCo 部署代码；部署侧只加载训练后的策略。前提是随机化范围应当覆盖真实机器人和 MuJoCo 模型可能存在的误差，而不是随意扩大范围。

先判断随机化在哪个时机生效：

| 类型 | 典型项 | 当前框架放置位置 | 生效频率 |
| --- | --- | --- | --- |
| 资产创建时的静态属性 | 地面摩擦、机身质量、碰撞形状属性 | `base/domain_rand.py` 的 property callback | 每个并行环境创建一次 |
| 回合重置时的状态 | 初始姿态、初始速度、命令、可重置的环境参数 | `base/legged_robot.py` 的 `reset_idx()`、`_reset_*()` | 每个 episode |
| 运行中的动态扰动 | push、外力、移动平台 | `post_physics_step()` 或其回调 | 按配置周期 |

不要把“每回合都要重采样”的逻辑写进资产创建 callback。环境在训练启动时只创建一次，写错位置会导致随机化只采样一次，和预期的每回合随机化不同。

#### 示例：新增静态的接触恢复系数随机化

以下以 `restitution` 为例，展示新增一个与摩擦同类的随机化项需要改哪些地方。

1. 在 `base/legged_robot_config.py` 的 `domain_rand` 声明默认关闭的字段：

```python
class domain_rand:
    # ...已有项...
    randomize_restitution = False  # 是否随机化碰撞恢复系数
    restitution_range = [0.0, 0.1]  # 恢复系数随机范围
```

2. 在 `go2/go2_config.py` 的 `domain_rand` 覆盖实际开关和范围：

```python
class domain_rand(LeggedRobotCfg.domain_rand):
    randomize_restitution = True
    restitution_range = [0.0, 0.05]
```

3. 在 `process_quadruped_rigid_shape_props()` 中直接读取 `randomize_restitution`，采样并写入 Isaac Gym 的刚体形状属性。应沿用现有摩擦随机化的“每个环境一个 bucket”模式，避免每个 shape 都独立随机而引入不必要的物理不一致：

```python
if env.cfg.domain_rand.randomize_restitution:
    if env_id == 0:
        low, high = env.cfg.domain_rand.restitution_range
        num_buckets = 64
        bucket_ids = torch.randint(0, num_buckets, (env.num_envs, 1))
        buckets = torch_rand_float(low, high, (num_buckets, 1), device="cpu")
        env.restitution_coeffs = buckets[bucket_ids]

    for shape_id in range(len(props)):
        props[shape_id].restitution = env.restitution_coeffs[env_id]
```

这个例子只展示接入结构。恢复系数会明显改变触地行为，Go2 平地 walk 不应一开始就打开大范围随机化；先从接近 `0.0` 的窄范围开始，确认不会破坏接触稳定性。

#### 回合级或动态随机化的额外要求

若新项不是资产静态属性，除了配置外还要选择正确的执行点：

- 每回合重置：在 `_reset_dofs()`、`_reset_root_states()` 或 `reset_idx()` 中只更新 `env_ids` 对应的环境，并在需要时调用 Isaac Gym 的 indexed setter 把结果写回仿真。
- 每控制步扰动：使用 GPU tensor 进行批量采样，避免在 4096 个环境上写 Python 循环；随后通过对应的 Isaac Gym tensor API 提交状态或力。
- 改变 PD、关节强度等控制参数：需要明确参数是每环境还是全局。当前 `p_gains` / `d_gains` 是每关节的一维共享值；若要按环境随机，必须先把它们扩展为 `(num_envs, num_actions)` buffer，并同步修改 `_compute_torques()`，不能只在配置里加一个范围。
- 新增外力并希望让 HIM critic 利用该信息：可以考虑更新现有 privileged external-force 槽位；不要随意改 actor 的 45 维单帧观测或 6 帧历史长度。改 actor/critic 维度会使 checkpoint 不兼容，并要求同步部署侧输入构造。

### 新增项的检查表

新增 reward：

- 在 `base` 配置声明默认字段并写中文注释。
- 通用项在 `base` 实现并在对应机器人配置给出启用值；机器人专有项放进对应适配器，避免污染通用层。
- 名称严格满足 `scales.<name>` 对应 `_reward_<name>()`。
- 函数返回 `(num_envs,)` 的 GPU tensor，使用批量运算。
- 有额外状态依赖时，在 `base/rewards.py` 声明，并确认对应 state tensor 已获取和刷新。
- 使用 reward scale 作为唯一启用开关，不再增加重复布尔 gate。
- 做 5 次迭代冒烟测试，并在 TensorBoard 确认 `Episode/rew_<name>`。

新增域随机化：

- 在 `base.domain_rand` 声明开关和范围，在机器人配置覆盖实际值。
- 实现逻辑直接读取对应 `domain_rand` 开关。
- 静态属性写进 rigid shape/body property callback；回合级和动态项写进 reset 或 post-step 流程。
- 只影响目标 `env_ids`，并使用相应 Isaac Gym setter 写回仿真。
- 随机范围从小开始；每次只增加一种随机化，先验证 reward、episode length 和 play。
- 不改变观测/动作/控制接口时可尝试 `--resume`；若改变 actor 或 critic 输入维度、动作维度或网络结构，则必须从头训练。

以下改动通常不需要同步部署侧：

```text
reward 公式和权重
摩擦、质量、恢复系数等训练域随机化
push、课程学习、训练噪声
PPO / HIM-PPO 超参数
```

以下改动必须同步部署侧，并重新核对导出的 TorchScript / ONNX 输入：

```text
actor 观测内容、顺序、缩放、历史帧数
动作维度、关节顺序、默认关节角
action_scale、kp、kd、控制周期
```

## 常见功能怎么打开

### 1. 打开 foot_clearance

用于鼓励足端离地，避免策略拖脚。当前已经打开。

只需要设置目标高度和非零权重：

```python
class rewards:
    clearance_height_target = -0.20

    class scales:
        foot_clearance = -0.01
```

注意：

- `foot_clearance` 依赖足端刚体位置和速度，框架会根据非零权重自动刷新 rigid-body state。
- 将 `foot_clearance` 设为 `0.0` 或 `-0.0` 就会关闭该项。
- 当前 `clearance_height_target = -0.20` 是机身坐标系下的足端目标高度，不是世界坐标直接抬 20 cm。

可调范围建议：

```text
foot_clearance = -0.005  # 很弱
foot_clearance = -0.01   # 常用起点
foot_clearance = -0.02   # 更强，可能导致动作变大或步态过高
```

### 2. 打开观测噪声

用于增强鲁棒性，当前已经打开。

```python
class noise:
    add_noise = True
    noise_level = 1.0
```

各项噪声：

```python
dof_pos = 0.01
dof_vel = 1.5
lin_vel = 0.1
ang_vel = 0.2
gravity = 0.05
height_measurements = 0.1
```

建议：

- 初期如果训练明显发散，可以先把 `noise_level` 降到 `0.5`。
- 不建议一开始把噪声放大到 `2.0` 以上。
- 噪声不会改变模型输入维度，可以在 checkpoint 上续训。

### 3. 打开摩擦随机化

当前已经打开：

```python
class domain_rand:
    randomize_friction = True
    friction_range = [0.5, 1.25]
```

建议范围：

```text
[0.7, 1.2]    # 更温和
[0.5, 1.25]   # legged_gym 常用
[0.3, 1.5]    # 更激进，建议步态稳定后再试
```

### 4. 打开机身质量随机化

当前关闭。

```python
class domain_rand:
    randomize_base_mass = True
    added_mass_range = [-1.0, 1.0]
```

建议先从小范围开始：

```text
[-0.5, 0.5]
[-1.0, 1.0]
```

质量随机化不会改变 obs/action 维度，通常可以续训，但会让短期 reward 下降。

### 5. 打开 push

当前关闭。push 会周期性给机器人一个平面速度扰动。

```python
class domain_rand:
    push_robots = True
    push_interval_s = 15
    max_push_vel_xy = 1.0
```

建议顺序：

```text
max_push_vel_xy = 0.3
max_push_vel_xy = 0.5
max_push_vel_xy = 1.0
```

push 比摩擦随机化更容易让训练短期变差。一般先有稳定步态，再打开。

### 6. 打开 command curriculum

当前关闭。用于根据速度跟踪表现逐步扩大命令范围。

```python
class commands:
    curriculum = True
    max_curriculum = 2.0
```

注意：

- 这会改变命令采样范围，训练曲线可能短期下降。
- 适合基础速度跟踪稳定之后打开。

### 7. 打开高度采样和地形

当前关闭：

```python
terrain.mesh_type = 'plane'
terrain.curriculum = False
terrain.measure_heights = False
```

如果只在平地训练，不需要打开。

如果之后要粗糙地形：

```python
class terrain:
    mesh_type = 'trimesh'
    curriculum = True
    measure_heights = True
```

注意：

- 当前 actor 外部输入仍是 270 维历史观测，不包含高度采样。
- 高度采样当前进入 critic privileged obs 的 187 维部分。
- 打开地形后训练难度明显增加，建议在平地策略稳定后再做。

## reward 参数怎么理解

当前 Go2 生效的主要 reward：

```python
tracking_lin_vel = 1.0
tracking_ang_vel = 0.5
lin_vel_z = -2.0
ang_vel_xy = -0.05
orientation = -0.2
dof_acc = -2.5e-7
foot_clearance = -0.01
action_rate = -0.01
smoothness = -0.01
torques = -0.0002
dof_pos_limits = -10.0
```

reward 权重会在环境初始化时乘以控制周期 `dt`。当前：

```text
sim.dt = 0.005
control.decimation = 4
训练控制周期 dt = 0.02
```

所以不要只看原始数字大小，还要知道实际计算时会乘 `0.02`。

### tracking_lin_vel

鼓励跟踪 x/y 速度命令。

```python
tracking_lin_vel = 1.0
tracking_sigma = 0.25
```

影响：

- 增大后更重视速度跟踪。
- 太大可能牺牲姿态稳定和动作平滑。
- 如果实际速度总是偏离命令，可以优先看这个和命令范围。

### tracking_ang_vel

鼓励跟踪 yaw 角速度。

```python
tracking_ang_vel = 0.5
```

影响：

- 增大后转向更积极。
- 太大可能导致转向时身体晃动。

### lin_vel_z

惩罚机身上下跳动。

```python
lin_vel_z = -2.0
```

影响：

- 过弱会跳动。
- 过强可能让步态不敢抬腿。

### orientation

惩罚机身 roll/pitch 倾斜。

```python
orientation = -0.2
```

影响：

- 增大负值后机身更平。
- 过强可能抑制自然动态步态。

### torques

惩罚力矩。

```python
torques = -0.0002
```

影响：

- 更负会省力，但可能脚抬不起来、速度上不去。
- 更接近 0 会动作更有力，但可能抖动和能耗变大。

建议调节：

```text
-0.0001   # 更允许用力
-0.0002   # 当前值
-0.0004   # 更省力但可能拖脚
```

### action_rate

惩罚相邻动作变化。

```python
action_rate = -0.01
```

影响：

- 更负会动作更平滑。
- 太强会让动作迟钝，脚抬不起来。

### smoothness

惩罚二阶动作变化。

```python
smoothness = -0.01
```

影响：

- 抑制高频抖动。
- 太强会限制快速摆腿。

建议：

```text
-0.005
-0.01
-0.02
```

### foot_clearance

鼓励足端在摆动时达到目标高度。

```python
foot_clearance = -0.01
clearance_height_target = -0.20
```

影响：

- 有助于解决不抬腿和拖脚。
- 太强可能导致步态夸张、能耗增加、落脚不稳。

建议优先调 `foot_clearance` 权重，再调 `clearance_height_target`。

### dof_pos_limits

惩罚关节接近位置极限。

```python
dof_pos_limits = -10.0
soft_dof_pos_limit = 0.9
```

影响：

- 减少关节打到极限。
- 太强可能压制动作幅度。

这是 Unitree Go2 配置里启用的项，当前已经打开。

### collision

当前关闭：

```python
collision = -0.0
```

用于惩罚大腿/小腿等非足端碰撞。

打开建议：

```text
collision = -0.2
collision = -0.5
collision = -1.0
```

不要一开始直接开到很大，否则可能抑制探索。

### feet_air_time

当前关闭：

```python
feet_air_time = 0.0
```

传统 legged_gym 常用 `1.0`，但 HIMLoco walk 配置里经常关闭或给得很小。

影响：

- 打开后可能更容易产生明显步态。
- 太大可能鼓励跳跃或过长腾空。

建议：

```text
feet_air_time = 0.1
feet_air_time = 0.2
feet_air_time = 0.5
```

不要一开始直接用 `1.0`，除非当前策略很稳但步态太保守。

## command 参数怎么调

当前 Go2：

```python
lin_vel_x = [-1.0, 1.0]
lin_vel_y = [-1.0, 1.0]
ang_vel_yaw = [-1.0, 1.0]
heading = [-3.14, 3.14]
resampling_time = 10.0
heading_command = True
```

### lin_vel_x

前后速度范围。

建议：

```text
[-0.5, 0.8]   # 更容易起步
[-1.0, 1.0]   # 当前
[-1.5, 1.5]   # 更难
```

如果策略还不会稳定走，先不要扩大到 `[-2, 2]`。

### lin_vel_y

侧向速度范围。

侧向对四足步态要求更高。若只想先训练前后走，可以暂时缩小：

```text
[-0.3, 0.3]
[-0.5, 0.5]
[-1.0, 1.0]
```

### ang_vel_yaw

偏航角速度范围。

当前已经从 `[-3.14, 3.14]` 收到 `[-1.0, 1.0]`，参考 legged_gym。过大的 yaw 范围会让早期训练更难。

### resampling_time

命令保持时间。

```python
resampling_time = 10.0
```

影响：

- 太短：命令频繁变化，训练更难。
- 太长：策略适应命令变化能力弱。

常见范围：

```text
5.0
10.0
15.0
```

## 控制参数怎么调

当前 Go2：

```python
stiffness = {'joint': 20.0}
damping = {'joint': 0.5}
action_scale = 0.25
decimation = 4
sim.dt = 0.005
```

### kp/kd

影响机器人跟踪目标关节角的力度。

```text
kp 太小：腿软，脚可能抬不起来
kp 太大：动作硬，容易抖动或仿真不稳定
kd 太小：阻尼不足，容易抖
kd 太大：动作迟钝，摆腿受限
```

当前是 Unitree Go2 常见安全配置：

```python
kp = 20.0
kd = 0.5
```

如果要改，必须同步部署侧：

```text
quadruped/src/controller/rl/config/go2.yaml
```

### action_scale

动作到目标关节角偏移的比例。

```python
target_joint_pos = default_joint_angle + action * action_scale
```

影响：

- 太小：动作幅度不足，脚抬不起来。
- 太大：动作激进，容易抖动或摔倒。

当前：

```python
action_scale = 0.25
```

改这个必须同步部署侧。

### decimation

每个策略动作持续多少个 Isaac Gym 物理步。

当前：

```python
decimation = 4
sim.dt = 0.005
control_dt = 0.02
```

改 decimation 会改变控制频率和 reward 缩放，也会影响部署侧控制周期。不要随便改。

## PPO / HIM-PPO 参数怎么调

当前：

```python
learning_rate = 1e-3
schedule = 'adaptive'
desired_kl = 0.01
clip_param = 0.2
gamma = 0.99
lam = 0.95
num_learning_epochs = 5
num_mini_batches = 4
entropy_coef = 0.01
max_grad_norm = 1.0
```

### learning_rate

影响更新幅度。

```text
1e-3   当前值，学习快但可能波动
5e-4   更稳
3e-4   更保守
```

如果出现 loss 剧烈波动、动作突然崩，可以尝试降到 `5e-4`。

### entropy_coef

鼓励探索。

```text
0.005  探索少，更稳但可能早熟
0.01   当前值
0.02   探索多，可能更慢或更抖
```

### desired_kl

自适应学习率的目标 KL。

```text
0.005  更保守
0.01   当前
0.02   更激进
```

一般先不动。

### num_steps_per_env

当前：

```python
num_steps_per_env = 24
```

增大后每次更新采样更多，可能更稳但显存和单次迭代时间增加。

常见：

```text
24
32
48
```

## 续训还是从头训练

适合 `--resume`：

- 只微调 reward 权重。
- 打开小范围噪声。
- 打开小范围摩擦随机化。
- 打开轻量 push。
- 调整 command 范围但不改 obs/action 维度。
- 调整 PPO 学习率、entropy 等。

不建议 `--resume`：

- 改了 actor obs 维度。
- 改了 history length。
- 改了 privileged obs 维度。
- 改了 action 维度。
- 改了网络结构。
- 改了关节顺序。
- 大改默认关节角、PD、action_scale。
- 从平地突然切到复杂地形且随机化全开。

当前已经固定为 `45*6` 和 HIM-PPO，之后如果只调 reward、noise、friction、push，通常可以续训。

## 推荐调参顺序

每次只改一个参数组，不要一次性全开。

当前已经做到：

```text
HIM-PPO + 45*6
smoothness
foot_clearance
noise
friction randomization
dof_pos_limits
```

后续建议顺序：

```text
1. 观察当前 foot_clearance 版本是否明显抬腿
2. 微调 foot_clearance 权重和 clearance_height_target
3. 小幅打开 collision
4. 小幅打开 feet_air_time
5. 打开 push，先 max_push_vel_xy=0.3
6. 打开 base mass randomization
7. 打开 command curriculum
8. 最后再考虑 rough terrain / height scan
```

如果机器人仍然脚抬不起来，优先考虑：

```text
foot_clearance: -0.01 -> -0.02
torques: -0.0002 -> -0.0001
action_rate: -0.01 -> -0.005
smoothness: -0.01 -> -0.005
lin_vel_y 范围缩小
```

如果机器人抖动严重，优先考虑：

```text
smoothness: -0.01 -> -0.02
action_rate: -0.01 -> -0.02
torques: -0.0002 -> -0.0004
learning_rate: 1e-3 -> 5e-4
noise_level: 1.0 -> 0.5
```

如果机器人速度跟踪过快或实际速度偏大：

```text
tracking_lin_vel 不一定要加大，先看 command_scale 和部署侧观测是否一致
缩小 lin_vel_x 范围
加大 torques 惩罚
加大 action_rate / smoothness
```

如果机器人容易摔：

```text
orientation: -0.2 -> -0.3
ang_vel_xy: -0.05 -> -0.1
lin_vel_z: -2.0 -> -3.0
缩小 yaw / lateral command 范围
降低 learning_rate
```

## 训练后怎么看是否有效

不要只看总 reward。至少看这些：

```text
rew_tracking_lin_vel     速度跟踪是否提升
rew_tracking_ang_vel     转向跟踪是否提升
rew_foot_clearance       抬脚约束是否稳定
rew_torques              是否为了抬脚导致力矩过大
rew_action_rate          动作是否变抖
rew_smoothness           二阶动作是否变抖
rew_dof_pos_limits       是否频繁接近关节极限
episode length           是否频繁摔倒
```

play 观察重点：

```text
脚是否拖地
脚是否抬得过高
机身是否上下跳
转向是否明显晃动
能否连续前进/后退
是否遇到侧向命令就崩
动作是否高频抖动
```

MuJoCo 部署观察重点：

```text
训练 play 和 MuJoCo 是否趋势一致
默认命令下速度是否明显偏大或偏小
摇杆命令是否持续响应
摔倒检测是否误触发
关节是否频繁打满
```
