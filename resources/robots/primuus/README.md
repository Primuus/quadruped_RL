# Primuus 训练资产

[训练首页](../../../README.md) | [任务配置](../../../quadruped_rl/envs/primuus/primuus_config.py)

本目录来自部署工程 `src/controller/rl/resources/robots/primuus/`，保留相同相对路径：

- `urdf/primuus.urdf`：训练导入入口，12个转动关节和8个固定关节，21个link。
- `stl/`：17个原始显示网格，足端碰撞仍引用原STL。
- `collision/`：大腿电机、板件来源、原156个凸分块和机身/四个髋部的5个等价凸包，共161个OBJ及20对命名自碰撞排除规则。

训练只需URDF及其引用资产；MuJoCo本体XML、场景XML和运行YAML仍由部署工程维护。训练运行不读取部署工作区，也不依赖Go2目录。

## 导入约定

- `collapse_fixed_joints=False`，保留四个足端和四个 `*_calf_collision_link`。
- `self_collisions=-1`，通过JSON排除正常装配接触，不关闭全部自碰撞。
- 足端选择 `_foot_link`；非足端接触选择 `thigh`、`calf`，后者包含小腿碰撞载体。
- 每个URDF collision对应一个凸形状，不再自动VHACD。
- 全机169个碰撞形状：机身1个，每腿髋1个、大腿37个、小腿3个、足端1个。77形状版本已撤销，恢复每腿32个原壁体和原长槽净空；原156个OBJ及电机/足端输入网格与部署历史 `d8806b4` 字节一致，不再使用 `*_thigh_shell_*` 或6 mm填充预算。
- 机身和髋部仅提取原网格的同一凸包，不缩放或近似顶点；它们与显示STL分离。不能仅为降低形状数量而填平活动通道，也不能直接用Go2的实心大腿盒体或尺寸替代。
- 原始小腿范围 `[-2.7227, -0.8378] rad`，每关节理想力矩上限 `23.7 N m`。
- 策略关节顺序为FL/FR/RL/RR，每腿hip/thigh/calf。默认角 `[0, -0.75, -1.5]`，不使用Go2姿态。

修改资产时，训练和部署两侧的URDF、引用网格、命名排除规则必须同步；URDF坐标、惯量和碰撞变动还须同步部署XML。不要用收紧机械限位代替碰撞修复。

Primuus任务的PD暂沿用Go2的 `20 / 0.5`，部署YAML已同步。当前版本已在本地MuJoCo检查200组站姿附近采样、PD站立、倒地和最大力矩折膝；运动学及质量矩阵与原169形状版本一致，折膝停止角逐项一致，仍约 `-2.617338 rad`。四条小腿各401个角度的本腿大腿与小腿/足端距离对比最大差异为0，代表截面长槽净宽已从77形状版的约23.22 mm恢复为原31 mm。它不代表任意关节角组合均无自碰撞。

`20 / 0.5` 默认角站立4 s末态机身Z约0.234 m，与原模型相同，但低于当前高度奖励的0.25 m容差下限，增益仍需后续评估。此次不改PD、奖励、质量惯量、关节坐标/限位、观测、过滤规则或Go2任务。碰撞输入源网格三角面数从110316降到54640，不能据此推断求解成本或GPU吞吐。

物理步长0.25 ms，PD每步更新，策略50 Hz，4096环境。原169形状模型GPU初始化曾出现底层内存越界，该问题尚未解决；当前版本尚未重做CPU/GPU PhysX导入和10轮训练验收，不能视为GPU训练已通过。本次仅修改本地工程，不改驱动、CUDA、PhysX、聚合容量或自碰撞开关来绕行。一次性检查脚本不加入正式链路。
